# 技術決策紀錄：植物人格實作策略 (AI vs. ML)

## 1. 背景說明
在「智慧盆栽」專案中，核心目標之一是賦予裝置「人格化」的特質，使盆栽能與使用者產生情感連結。我們針對實作技術進行了深度探討，特別是在考量樹莓派 5 (Raspberry Pi 5) 硬體效能與系統穩定性的前提下，評估了兩種主要技術路徑。

## 2. 技術路徑評估

### A. 大語言模型路徑 (LLM / Ollama)
- **實作方式**：使用 Ollama 跑輕量級模型（如 TinyLlama 或 Phi-3）。
- **優點**：具備強大的語言生成能力，能進行自然的自由對話。
- **缺點**：對 CPU/RAM 負擔較重，且對話結果具備不確定性（幻覺問題）。

### B. 傳統機器學習路徑 (ML / Random Forest / Decision Tree)
- **實作方式**：
    1. 將感測器數據（濕度、溫度、互動頻率等）作為 **特徵矩陣 (Feature Matrix)**。
    2. 使用 **隨機森林 (Random Forest)** 或 **決策樹 (Decision Tree)** 進行分類，預測植物當下的 **情緒狀態 (Emotion State)**（如：開心、憂鬱、傲嬌、睡眠）。
    3. 根據預測的情緒，從預設的語料庫中選取回應或變更 UI 表情。
- **優點**：運算需求極低、反應即時、邏輯完全可控且可解釋。
- **缺點**：無法進行自由對話，行為模式較為固定（類似電子雞）。

## 3. 實作決策：混合式 AIoT 架構

經過討論，我們決定採取 **「混合式」** 的開發策略，以確保系統在資源受限下仍能展現豐富人格：

1.  **情緒決策層 (ML Layer)**：
    - 優先考慮使用機器學習（如隨機森林或加權計分模型）來處理「行為情緒」。
    - 系統會持續監測環境數據，並即時產出植物的「心情指數」。
2.  **表現層 (Interaction Layer)**：
    - **輕量模式**：根據心情指數，顯示對應的表情符號 (SVG/Emoji) 或播放無意義的寵物式音效/對話。
    - **深度模式 (選配)**：當使用者主動發起複雜對話時，系統才會喚醒 **Ollama (Edge AI)**，並將 ML 層產出的「心情」傳遞給 LLM 作為 System Prompt 的參考背景。

## 4. 專案定位
本專案定義為 **AIoT (Artificial Intelligence of Things)**。
- **IoT** 負責環境感知與硬體執行（ESP32）。
- **AI** 負責邊緣端的智慧推論與人格模擬（Raspberry Pi ML/LLM）。

## 5. 結論
透過機器學習（Random Forest）賦予植物人格是完全可行且具備高效率的方案。它將系統從單純的「自動化澆水機」升格為具備「心理狀態」的「數位生命體」。
